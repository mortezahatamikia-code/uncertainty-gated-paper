# Taste
- Never run any git command (commit, add, reset, checkout, status, log, etc.) — the user manages version control themselves and commits on their own; after code or paper edits, just report what changed and stop. Confidence: 0.95
- When asked to read/familiarize with code or a paper as groundwork, does not want a recap of what was understood — just absorb it silently and report readiness briefly, then wait for the next instruction. Confidence: 0.6
- Prefers artifact/footprint sizes (APK, model binaries) reported as approximate values (`≈`, one decimal) with an explicit unit definition (e.g. MiB = 2^20 bytes), while accuracy/F1/FNR/latency stay exact with ± and CIs. Confidence: 0.7
- Wants reported numbers regenerated from real builds (re-export models, rebuild the APK) and verified before they are written into documents, rather than reusing existing figures. Confidence: 0.6
- When a review finds a claim or table lacks supporting evidence, expects the agent to write and run the experiment itself and insert the resulting text, instead of handing back a list of things the user must arrange; each new run is written to a fresh results file labeled with the current date rather than overwriting an existing artifact. Confidence: 0.7
- Requires every number in the manuscript to come from the canonical pipeline/experiment set: results produced by side or variant branches (e.g. a separate morphopath copy of the paper and pipeline) must be purged and replaced with real values, not merely relabelled. Confidence: 0.65
- Wants deliverable folders to be self-documenting: a README.md inside the folder that explains what each file is for, which stage it belongs to, where/when each is used, with citations to the official, current source (with access date). Confidence: 0.6
- Expects claims in deliverables to be verified against primary sources rather than trusted from memory — e.g. asking for every newly added bibliography entry to be checked as real (with correct authors/pages/year), for duplicates/no-citation entries to be swept before submission, and for every citation in a section to be checked that it actually supports the claim it backs (swapping out ones that do not, and supplying an accurate reference wherever an unsupported sentence needs backing). Confidence: 0.85
- When auditing changes made in a recent time window, wants the window reconstructed from version-control history (including edits not yet committed) and every addition or removal judged individually: was it real, was it genuinely needed, and does the cited source actually assert the claim now attached to it — so a wrong or unnecessary deletion/addition surfaces rather than being assumed fine. Confidence: 0.7
- Keeps the introduction high-level: concrete hyperparameters and threshold values (e.g. a specific gate threshold) belong in the methodology section, not the introduction. Confidence: 0.6
- Prefers academic prose to read as human and natural: is straightforward, avoids AI phrasing patterns, excessive/repetitive adjectives, promotional tone, and list-like "First/Second/Third" enumerations inside a paragraph; uses longer sentences as long as they stay simple and readable (a choppy string of short sentences reads as uniform and AI-generated); and varies sentence length and openings so the tone is not dry or monotonous, but keeps the overall tone consistent rather than overly varied or confusing — all while preserving the original information. Confidence: 0.9
- Prefers to review and approve proposed edits (shown in chat) before they are written to files; proposals should be given as exact verbatim before/after text (quoted in full, with location) rather than a paraphrase or bullet-point summary of what changed, and where a fix admits alternative wordings every option must be listed with the reason for each (and a recommendation) instead of silently choosing one. Confidence: 0.75
- When editing a paper, expects each change to be integrated with the document as a whole rather than patched locally: new subsections/rows must be propagated to section numbering, the introduction's roadmap, cross-references, and the places where the material is discussed elsewhere, and the author should be told what was affected. Confidence: 0.6
- Wants paper sections to avoid repeating material already stated elsewhere (e.g. the Related Work must not re-repeat definitions, problem statements, system numbers, or contribution details from the Introduction); each section should present only information that belongs to it, organized logically, while keeping the tone consistent with the rest of the paper. Confidence: 0.6
- Wants paper structure reorganized so each analysis stands on its own: ablation study and efficiency analysis should be clearly separate sections rather than buried as subsections of Results — and the restructuring must be purely structural, moving the existing text verbatim so the context and wording are not changed. Confidence: 0.65
- Wants paper prose kept short and simple while staying academic: cut anything over-explained, anything that sounds defensive/self-justifying (e.g. repeatedly insisting a choice "never" affects something, or pre-emptively arguing against objections), and anything repetitive — one clear statement of each conclusion instead of restating it in several sentences. Confidence: 0.8
- Wants results prose in a paper to explain what the numbers mean rather than recite values already visible in the tables: state the finding and the reason for it, drop long enumerations of per-row percentages, and keep the text flow simple and easy to read. Confidence: 0.75
- Wants citations in a paper to appear in non-decreasing chronological order: each reference's year must be >= the preceding citation's year and <= the following citation's year. Confidence: 0.8
- Prefers the manuscript's references and comparison baselines to be recent, deliberately omitting works older than 2022 except the unavoidable foundations the method stands on. Confidence: 0.55
- When criticism or advice comes from an outside reviewer/collaborator, wants a complete self-contained reply written for that person (ready to forward as-is): which data was found, what was changed and why, and which parts of the advice were accepted or rejected with the evidence for each. Confidence: 0.5
- Prefers diagrams and figures to be visually clear and easy to read: high-contrast colors and legible text, avoiding pale/washed-out grays and low-contrast labels. Confidence: 0.6
- Prefers figures, plots, and tables to be sized compactly so they take up less page space, as long as their content stays intact and nothing overflows or gets mangled; figures may be shrunk (width and hence height) but their aspect ratio must be preserved. Confidence: 0.65
- Wants paper figures free of in-plot titles — that information belongs in the LaTeX caption instead — and included as vector (PDF) output with embedded fonts so labels and cell annotations stay sharp at journal-column size. Confidence: 0.6
- Prefers concise table captions that give only the title/essential units, with any explanatory detail moved into the surrounding body paragraph text rather than packed into the caption; also wants large tables made readable (e.g. separating row groups with rules). Confidence: 0.8
- Requires every acronym in a paper to be defined at its first use, with no exceptions anywhere in the manuscript. Confidence: 0.85
- Wants LaTeX table/section sources to use standard math commands (`$\Delta$`, `$\downarrow$`, `$\hat{\rho}$`, …) instead of raw Unicode symbols, since Unicode glyphs get dropped or mangled on the way to the PDF (e.g. `â`, `(4)` printed where `$\hat{\rho}$`/`↓` was intended) — check the rendered PDF for missing/placeholder header symbols, not just the source. Confidence: 0.6
- Before submission, wants the manuscript conformed to the target journal's official formatting requirements (font and encoding, heading styles left to the journal class, body font size, page margins, table spacing) and the compiled PDF verified clean — no `[?]`/undefined citations (full pdflatex+bibtex+rerun build), no stretched justified lines, no overfull boxes. The same verification is expected after any substantive round of edits: recompile, review the diff, and confirm nothing broke and no number, equation, table, or citation changed — wording revisions must not alter the original meaning. Confidence: 0.75
- When stopping mid-task, wants a written handoff for the next agent rather than a resolution in that session: what the error is, which changes are already applied, what still has to be updated in code and text, and which commands still need to be run — and where the root cause is not known, says so explicitly (flags it as "needs investigation") instead of guessing at an explanation. The handoff must be fully self-contained on the assumption that the next agent has zero context: restate the original task and its instructions, the background the work depends on, the discovered issues, and the current state, rather than only the delta since the last report. Confidence: 0.8
- When handed an external list of criticisms (reviewer report, checklist of alleged errors), expects each item checked against the actual files and classified as real vs. false before anything is changed — citing the file/line/artifact that confirms or refutes it — rather than trusting the list or fixing everything blindly; false positives and claims that cannot be verified from the source text should be reported as such. Confidence: 0.65
- Before a baseline comparison is run, wants the choice of that baseline justified rather than assumed: that it is the same class of object as the proposed method (same frozen features, training-free, so the comparison is apples-to-apples), that it is a strong and standard published reference point with its release year/standing stated from primary sources, and that omitting it would be the worse methodological error. Confidence: 0.55
- Judges a competing method as a threat to the paper on more than accuracy: expects the comparison to also settle its model size / memory footprint, whether it can realistically run on an edge device, and its inference speed relative to the proposed method — and the paper's scientific standing to be reassessed honestly on all those axes rather than on the accuracy gap alone. Confidence: 0.6
- Wants a paper's quantitative claims to be internally consistent: the same metric should carry the same value across introduction, figures, methodology, and result tables; when two values come from different evaluation conditions, one is kept as the headline and the other is stated with its own context (or both are given as a range), rather than left looking contradictory to a reviewer. When a key descriptor (e.g. a size/footprint breakdown) is settled on, expects that exact phrasing propagated to every place it appears (abstract, highlights, conclusion, body) rather than paraphrased differently in each. Confidence: 0.75
- When asking for a revision pass over recently added paper text, wants the scope limited to prose that genuinely changed in substance (not edits that only changed a number), and any sentence that already reads well left untouched — no blanket rewriting for its own sake; the revision must also not damage the scientific content. Confidence: 0.65
