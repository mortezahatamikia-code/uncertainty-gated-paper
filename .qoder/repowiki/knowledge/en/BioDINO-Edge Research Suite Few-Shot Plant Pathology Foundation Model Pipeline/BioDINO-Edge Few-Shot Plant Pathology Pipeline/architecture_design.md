The module is organized as a flat collection of Python scripts plus one notebook, split into three internal layers:
- Core math layer (`core_math.py`): pure NumPy/PyTorch primitives — Shannon margin-entropy confidence, regularized Fisher LDA (sklearn `LinearDiscriminantAnalysis` with Ledoit-Wolf shrinkage), L2-normalized class prototypes, convex late-fusion ensemble of visual LDA + text prototype probabilities, and closed-form transductive pseudo-label refinement.
- Data layer (`data_engine.py`): PyTorch `Dataset` (`PairDataset`) that opens each image once and emits both BioCLIP and DINOv2 transforms; resolvers for PlantVillage (`resolve_plantvillage_path`) and PlantDoc (`resolve_plantdoc_paths`) directory layouts; deterministic few-shot support/query partitioning via `load_plantvillage` / `load_plantdoc`; augmentation helpers (`extract_norm_stats`, `build_augmentation_pipeline`).
- Orchestration layer: multiple entry-point pipelines (`biodino_edge_pipeline.py`, `biodino_hierarchical_pipeline.py`, `biodino_v3_pipeline.py`) plus the all-in-one Jupyter notebook (`biodino_unified_pipeline.ipynb`) that wires backbones, data loaders, core math, and benchmarking. A separate `benchmark_engine.py` runs 30-episode Monte Carlo (PlantVillage) and 50-episode 5-way episodic (PlantDoc) protocols with CI95 reporting and INT8 latency profiling.

Dependency direction is strictly one-way: orchestration scripts import from `core_math` and `data_engine`; `core_math` has no intra-module dependencies; `data_engine` imports only `taxonomic_prompts`. All scripts use a dual-import shim (`try: from pipeline.X ... except ImportError: from X ...`) so they run either as package members or as standalone scripts. Taxonomic knowledge lives in `taxonomic_prompts.py` as curated multi-sentence botanical descriptions per class, used to build zero-shot text prototypes for BioCLIP. The `plantdoc_samples/` directory holds four sample images used by demo/saliency generation scripts.
